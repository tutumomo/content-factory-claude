# NSFW 總開關：可行性與邊界評估

日期：2026-11-25
狀態：**評估，未實作**

## 先回答你的問題

**可以做到「使用者看不到」，但做不到「LLM 看不到」——除非把資料真的搬走。**

這兩件事的難度天差地別，所以下面分開講。結論是：

| 目標 | 可行性 | 做法 |
|---|---|---|
| 關閉後，UI 看不到任何 NSFW 內容 | **可以，且可靠** | 單一守門點 + 全部讀取路徑過濾 |
| 關閉後，本機 LLM 的**新請求**看不到 NSFW | **可以** | 提示詞組裝時就把內容抽掉 |
| 關閉後，LLM「理論上」看不到 | **不能保證** | 見第 4 節：模型權重裡本來就有 |

第 4 節是這份評估最重要的一段，請先看那個再決定要不要做。

## 1. 「關閉」要關掉什麼

先定義清楚，這是整個設計的基礎。我建議分成兩個層級，不要只有一個開關：

```
nsfw.enabled = false        # 總開關：UI 與 LLM 都看不到
nsfw.enabled = true
  nsfw.allow_generate = false   # 看得到既有內容，但不能新生成
  nsfw.allow_generate = true    # 全開
```

只做一個開關的話，「我想保留作品但不能再生產」這個很常見的需求就沒有位置。

## 2. 使用者看不到：目前有 7 個洩漏點

我把現有程式碼每個會吐出 NSFW 資料的地方都列出來，這是實作時的清單：

| # | 位置 | 現況 | 需要 |
|---|---|---|---|
| 1 | `GET /api/episodes`（`store.list_episodes`） | 回全部集數 | 依 `ep["rating"]` 過濾 |
| 2 | `GET /api/episodes/{eid}`（`main._ep`） | 任何 id 都回 | 受限集數回 404 |
| 3 | `GET /files/{path}` | **只檢查第一層目錄名，不看分級** | 受限集數的檔案要 404 |
| 4 | `GET /api/styles` | 內建 NSFW 卡已受頻道上限管制，但**使用者自建的 NSFW 卡沒有** | 依卡上的 `nsfw` 過濾 |
| 5 | `GET /api/characters` | 回全部角色卡，含成人描述 | 依卡上的分級過濾 |
| 6 | `GET /api/prefs`（品味紀錄） | 含成人相關的寫作規則 | 標記過的規則要藏 |
| 7 | `GET /api/meta`、`/api/health` | `nsfw_topics`、`max_rating` 等字串 | 開關關閉時不要回這些 |

**第 3 點是目前最實際的洞，而且實測確認了。** `app/main.py` 的檔案服務只驗證「第一層目錄在允許清單裡」：

```python
if p.relative_to(root).parts[0] not in _FILES_ROOTS:
    raise HTTPException(404)
```

`episodes` 在清單裡，所以任何人知道路徑就能直接抓檔。實測（限制級集數 `20261124-114652-30如狼-40如虎`）：

```
GET /files/episodes/20261124-114652-30如狼-40如虎/brief.json   → 200
GET /files/episodes/20261124-114652-30如狼-40如虎/sources.md   → 200
GET /files/episodes/20261124-114652-30如狼-40如虎/episode.json → 200
```

抓回來的 `brief.json` 完整包含成人題材的切角與內容。開關關閉後如果只擋列表，檔案還是抓得到——這等於沒關。

**正確的做法是單一守門點。** 現在集數相關的讀取散在各處，我建議：

```python
# app/store.py
def visible_episode(eid: str) -> dict | None:
    """The episode, or None when it exists but must stay hidden (NSFW switch off)."""
```

所有端點都走它，包含 `/files`（先從路徑回推 episode id，再判斷）。這樣只會有一個地方需要測，不會漏。

## 3. LLM 看不到：提示詞層面可以做

這是可做的，而且不難，因為所有 LLM 呼叫都經過少數幾個入口：

```
prompts.base_system()     ← 頻道定位、風格卡、品味紀錄（每一次呼叫都帶）
prompts.brief/script/...  ← 各自的任務內容
llm.complete()            ← 唯一的出口
```

關閉時要做三件事：

1. **`base_system()` 抽掉 NSFW 素材**：`style_block()` 不給 NSFW 卡、`prefs_text()` 濾掉成人規則、`channel_block()` 抽掉 `max_rating` 與 `nsfw_topics`
2. **任務內容不含受限集數**：`sources_text()`、`_character_block()` 都不帶受限資料
3. **`llm.complete()` 加一道最終檢查**：送出前掃一次，命中 NSFW 標記就拒絕送出並記 log

第 3 點是保險，不是主力。主力是第 1、2 點「一開始就不放進去」，因為事後掃描永遠可能漏。

**但這裡有一個必須講清楚的事實**：這只能保證「不送出」。模型權重裡本來就有這些知識，你關掉開關也不會讓它忘記——就像你關掉瀏覽器，你的記憶還在。所以「LLM 看不到」在技術上只能是「我們不傳給它」，不能是「它不知道」。

## 4. 最重要的一段：這不是安全機制

如果你要的是一個**能防住的人**（例如共用電腦、要給別人看、擔心被誤觸），這個開關**有用但不夠**：

| 威脅 | 開關能不能擋 |
|---|---|
| 不小心點到、誤觸生成 | **能**，這是它最有效的場景 |
| 共用電腦上家人/同事看到 | **能**，前提是 UI 與檔案都擋好 |
| 有人刻意去找 | **不能**。資料還在磁碟上，改個設定檔就回來 |
| 已經送出去的內容 | **不能**。LLM 的輸出、發布包、YouTube 都收不回 |

所以定位要清楚：**這是一個「防誤觸」的開關，不是「防有心人」的鎖。** 如果你要的是後者，正確做法是**分離資料目錄**（`CF_DATA` 指到另一個資料夾），而不是開關：

```bash
CF_DATA=~/content-factory-sfw ./run.sh     # 完全看不到另一份資料
```

這件事我們在設計文件第 8 節已經寫過。開關適合「同一份資料裡，某些集數暫時不要出現」；不同資料夾適合「這兩種內容不該存在一起」。

## 5. 關閉時的行為要定義清楚

這是實作時最容易出錯的地方。我建議：

| 情境 | 行為 |
|---|---|
| 已開啟的受限集數頁面 | 下次輪詢（5 秒內）顯示「此集數已隱藏」，不是空白 |
| 跑到一半的受限集數 | **暫停**，不是刪除。開關打開後可續跑 |
| 佇列裡的受限集數 | 不執行，狀態標「暫停（NSFW 已關閉）」 |
| 既有發布包 | 留在磁碟，但 `/files` 不給 |
| 上傳中的 YouTube 任務 | 開關關不掉已經送出的請求，只能記錄 |

「跑到一半要暫停」這點特別重要：如果關閉時把它標成 error，開關打開後使用者得手動重跑，很容易忘記跑到哪。

## 6. 開關本身要放哪裡

三個選項，我建議第 2 個：

| 方案 | 說明 | 評價 |
|---|---|---|
| 存在 `settings.json` | 跟其他設定一起 | **不行**：關掉之後還看得到 `nsfw.enabled` 這個字串，而且改檔案就能繞過 |
| 存在獨立的 `nsfw.lock` 檔 | 檔案存在＝開啟 | 好：可以只刪檔就強制關閉，也看不出裡面有什麼 |
| 用環境變數 | `CF_NSFW=0 ./run.sh` | 也對，但重啟才生效 |

建議：**獨立檔 + 環境變數可強制覆蓋**。`CF_NSFW=0` 永遠優先，即使檔案存在。這樣可以「這台機器一律不開」，不用改資料。

## 7. 需要多少工作

| 項目 | 估計 |
|---|---|
| 開關本體 + `visible_episode()` 單一守門點 | 半天 |
| 7 個洩漏點逐一接上（含 `/files` 的路徑→集數回推） | 一天 |
| 提示詞層面（`base_system`、`style_block`、`prefs_text` 過濾） | 半天 |
| 佇列暫停、狀態顯示、前端隱藏 | 半天 |
| 測試（每個洩漏點一個測試，含 `/files` 直連） | 半天 |
| **合計** | **約 3 天** |

測試特別重要：這種「漏一個地方就等於沒做」的功能，必須每個點都有測試，而且要測「知道路徑直接抓檔」這種情況。

## 8. 我的建議

1. **做，但定位成「防誤觸」**。這個價值是真的：不想看的時候不會被推到眼前。
2. **不要宣稱「LLM 看不到」**。準確的說法是「不會把 NSFW 內容送給 LLM」。這兩者在技術上不同，寫在使用者文件裡要誠實。
3. **如果你要的是真的隔離，用 `CF_DATA` 分目錄**，成本低得多，效果強得多。
4. **優先做 `/files` 的修補**——不管開關做不做，這個洞現在就在：任何人知道路徑就能抓到檔案。

## 未驗證
